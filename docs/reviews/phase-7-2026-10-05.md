## P1 findings

### 1. The CLI cannot compile after the UpOptions change

[crates/rustlet-cli/src/compose.rs:267](../../crates/rustlet-cli/src/compose.rs#L267) initializes `UpOptions` without the new `always_recreate_deps` field. `cargo test -p rustlet-compose -p rustlet-cli` fails with E0063. This is an unfinished integration change from the previous review and prevents the CLI and workspace validation from completing. Supply the new option consistently at callers and expose or default its intended behavior.

### 2. Compose down -v can delete an explicitly external volume

[crates/rustlet-compose/src/load.rs:288](../../crates/rustlet-compose/src/load.rs#L288) drops declared resources that enabled services do not reference. [run.rs:304](../../crates/rustlet-compose/src/run.rs#L304) derives its external-volume protection set from that incomplete model, then removes project-labelled volumes.

Confirmed with the current library against the existing fake daemon:

1. Bring up project `shop` with service `app` mounting `data:/data` and joining network `legacy`; this creates project-labelled `shop_data` and `shop_legacy`.
2. Remove those service attachments, retaining top-level declarations `data: {external: true, name: shop_data}` and `legacy: {external: true, name: shop_legacy}`.
3. `down` with `volumes: true` removes both resources. The fake daemon records the DELETE requests and both disappear.

The same omission affects resources referenced only by disabled-profile services. Keep external declarations available for teardown even when provisioning filters unused resources. [Compose external-volume semantics](https://compose-spec.github.io/compose-spec/07-volumes.html#external) and [Docker's teardown implementation](https://raw.githubusercontent.com/docker/compose/main/pkg/compose/down.go) support keeping them.

A second, source-confirmed route bypasses protection: [CLI compose.rs:452](../../crates/rustlet-cli/src/compose.rs#L452) ignores `COMPOSE_FILE` when deciding whether a file exists. From a directory without a default compose file, `COMPOSE_FILE=/path/prod.yaml rustlet compose -p shop down -v` takes the fileless `down_project` branch and never reads that file's external declarations. This route could not be executed through the current CLI because finding 1 blocks compilation.

### 3. A small Containerfile can abort the entire daemon

[crates/rustlet-build/src/expand.rs:208](../../crates/rustlet-build/src/expand.rs#L208) recursively expands nested substitutions without a depth limit. A roughly 120 KB Containerfile containing `FROM scratch` and `ENV VALUE=` followed by 20,000 nested `${A:-...}` expressions fits below the daemon's 1 MiB Containerfile limit.

A privileged probe sent that file to an isolated, newly built daemon. Its Tokio worker overflowed its stack and the process aborted. The client received unexpected EOF, and a subsequent version request received connection refused. Claude's existing child-process regression independently fails with the same cause. Bound nesting or use an iterative parser so invalid input returns a build error.

## Lower-priority findings and limits

- **P3:** [op.rs:116](../../crates/rustlet-build/src/op.rs#L116) shell-expands MAINTAINER text. `Pat O'Brien` fails with an unterminated quote, and `$NAME` is substituted. Existing regression fails; raw text should be retained.
- **P3:** [parser.rs:820](../../crates/rustlet-build/src/parser.rs#L820) accepts invalid `ONBUILD CMD [1, 2]` despite rejecting that CMD directly. Existing regression fails. Executing base ONBUILD triggers is already a documented omission, which limits impact.
- **P3:** [copy.rs:860](../../crates/rustlet-image/src/copy.rs#L860) drops hardlink tracking too early. Copying hardlinked sources `a.txt b.txt a.txt` leaves separate destination inodes. Existing unit regression fails. This concerns Rustlet's preservation promise; Docker's cross-source behavior differs.
- **P3:** [diff.rs:377](../../crates/rustlet-image/src/diff.rs#L377) compares a directory with lower entries hidden by an upper opaque ancestor, potentially dropping a newly created directory above an excluded mount. A synthetic unit counterexample is confirmed; daemon reachability was not established.
- [extensions.rs:63](../../crates/rustlet-image/src/unpack/extensions.rs#L63) applies an empty PAX path instead of keeping the header name; [unpack.rs:310](../../crates/rustlet-image/src/unpack.rs#L310) panics in debug on a malformed double-minus timestamp; non-UTF-8 xattr names fail diff after lossy decoding. Existing uncommon/malformed-metadata regressions fail.
- [unpack.rs:277](../../crates/rustlet-image/src/unpack.rs#L277) deduplicates xattrs quadratically. Complexity is code-confirmed; a debug-only four-second threshold does not establish release severity.
- The fileless CLI down branch passes raw `-p` at [compose.rs:212](../../crates/rustlet-cli/src/compose.rs#L212). `-p SHOP up` normalizes to `shop`, while fileless `-p SHOP down` targets the uppercase spelling and silently misses it. Source-confirmed; CLI execution blocked by finding 1.

Documented omissions were not counted as findings: empty filesystem diffs still producing layers, >=8 GiB PAX sizes being unsupported, base ONBUILD execution, BuildKit-only features, other platforms, parallel Compose startup, anonymous-volume preservation on recreation, and future rootless behavior. The tentative commit/ONBUILD compatibility concern was withdrawn after checking Docker's config merge.

## Resolution and final validation — 2026-10-05

All supported findings above are resolved on `phase-7`. The earlier Claude fixes were preserved and integrated. Parser/op/context regressions were folded into their maintained modules, the duplicate Compose review scratchpad was removed after checking equivalent coverage, and invalid archive fixtures and obsolete refusal/profile/replacement assertions were corrected.

- Builder: nesting capped at 64, supplied ARG defaults selected before expansion, inherited stage ARGs retained, literal COPY sources planned consistently, parser/escape/heredoc/ONBUILD/MAINTAINER/duration/platform/ignore cases corrected. Ignored or outside Containerfiles travel only as a daemon-removed sidecar. WORKDIR creates directories as the selected user and records a cached layer. Unsupported realtime stop signals are refused explicitly, including imported image defaults at create.
- Images: only the active overlay namespace controls whiteouts and filtering; inactive attributes remain data through commit, unpack and copy. Manifests serialize canonical object order. Consecutive PAX state is replaced and bounded, empty path overrides fall back, invalid timestamps fail without overflow, repeated hardlinks remain linked, opaque ancestors participate in comparisons, and xattr deduplication avoids quadratic scans. Non-UTF-8 or `=` attribute names receive a clear refusal.
- Compose/API: every external resource declaration remains protected during teardown, including unused/profile-only declarations; creation still selects only used resources. Discovery, project names, named profile services, canonical port merges, shared-image build ownership and build completion are corrected. Explicit empty commands and removed environment keys survive normalization, container start and commit via `clear_cmd`/`unset_env`.
- Health/client/desktop: the shim kills disconnected internal healthchecks, while ordinary exec behavior stays compatible. Upload failures preserve received daemon reasons or report a clear interrupted-upload fallback with exit 125; source failures are not blamed on the daemon. The desktop caps both partial lines and total output per build step, reports discarded text, and includes the earlier dialog/health/stack/dashboard fixes.
